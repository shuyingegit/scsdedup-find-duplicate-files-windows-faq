Find duplicate files on Windows by content, not by name

Short answer: hash the files and group the ones whose content is identical - that finds the copies that were renamed, moved or dragged out of an archive, which sorting by name never will.

ScsDedup does this on Windows. It is not a WebDAV/NAS mount (ScsDrive), not a folder→drive-letter map (ScsSubst) and not a C: expand tool (ScsExpand).

How does it decide that two files are duplicates?

By content, not by name. Each file is hashed (SHA-256), and files whose full hashes match end up in one group. So a copy that was renamed or moved is still found, while two files that merely share a name, a size and a timestamp are not duplicates - size and date are only used to narrow the work down before the full hash is computed.

Does it delete anything?

No. The scan produces a report: duplicate groups with their paths and how much space each group wastes, sorted by the reclaimable amount, exportable as HTML or CSV, with the folder or the path one click away. Which copy you keep stays your decision.

The installer is about 2.4 MB, and the interface and the report are available in Chinese, English, Japanese, Korean, Spanish, French, German and Russian.

What it will not tell you

  • It finds identical files. A re-encoded photo, a re-muxed video or a document saved again from Word is a different file, and no hashing will call it a duplicate.
  • Files that are byte-identical but intentionally kept - the same asset in two projects, a config file that must stay where it is - are listed too. The report is evidence, not a verdict.
  • A large disk takes time: the scan works in three passes (size buckets, sampling, then full hashing). It runs locally; nothing is uploaded.
  • The free tier gives one report, so it is worth picking the drives to scan before you start.
