# FAQ：在 Windows 上找重复文件

最常被问到的一句是「怎么把我忘了的那些副本找出来」，而常见的回答——按名字排序然后肉眼扫文件夹——只能找到那些名字没被改过的重复。先做利益披露：ScsDedup 是我们做的（https://dedup.scsoi.com/），所以提到产品的地方请当成有倾向；下面的 Windows 行为本身不是我们的说法。

## 它凭什么判定两个文件是重复？

看内容，不看名字。每个文件都算一次哈希（SHA-256），哈希完全相同的文件归为一组。所以：

- 改过名、挪过别的目录、甚至是从压缩包里拖出来的那份副本，一样能找出来；
- 同名但内容不同的，不算重复；
- 大小和时间戳都相同的也不一定——大小和日期只用来把候选范围缩小，最后还是比全量哈希。

## 它会替我删文件吗？

不会。扫描结果是报告：每组重复的文件路径，以及这一组浪费了多少空间，按可回收空间排序。可以导出 HTML 或 CSV，可以打开所在目录、复制路径。保留哪一份、删不删，全由你决定。我更愿意把证据交给你，而不是让一个工具替你猜你想扔掉什么。

## 它不会告诉你的事

几个诚实的限制，也正是容易踩坑的地方：

- 它找的是**完全相同**的文件。重新编码过的照片、重新封装过的视频、从 Word 里另存一次的文档，都是不同的文件，哈希再准也认不出来。
- 字节相同但本来就该各留一份的文件——两个项目里同一份素材、必须放在原位的配置文件——同样会被列出来。报告是证据，不是判决。
- 盘大了就慢。扫描分三步（按大小分桶、采样、再全量哈希），老硬盘会让你等。全程在本地跑，不上传任何东西。
- 免费版只有一次报告，所以开始之前值得先想清楚扫哪几个盘。
